Why this player exists

    

      Three things break video playback on real phones: a codec the chip does not have, an app with
      no diagnostics, and a player that hides the trade-off between battery and compatibility. This
      project attacks all three.
    


    

      

        
Coverage

        
Two decoder paths

        
Media3/ExoPlayer runs the phone's hardware decoders first. When a file needs something the
          SoC cannot do, bundled FFmpeg decoders (NextLib) take over. Priority is a setting, not a
          secret.

      

      

        
Diagnostics

        
Logs built for bugs

        
Rotating log files, crash capture with stack traces, device and MediaCodec inventory, and
          export as .txt or .zip — share it or save it to Downloads.

      

      

        
Privacy

        
No internet permission

        
The manifest has no INTERNET permission. Your videos and logs cannot leave the
          device except through the share sheet you trigger.

      

      

        
Controls

        
Common gestures

        
Swipe for brightness and volume, double tap to seek, long press for 3× speed, control lock,
          aspect modes, subtitles from disk, picture-in-picture.

      

      

        
Library

        
Finds your files

        
MediaStore scan with live refresh, thumbnails rendered from the video, search, folder
          chips, seven sort orders, grid or list.

      

      

        
Transparency

        
Shows the streams

        
While watching, the info panel names the exact video, audio and subtitle formats that were
          selected, plus a full diagnostics copy button.

Send a bug report that actually helps

    
    
      
  1. Reproduce the problem once, so the failure sits at the end of the log buffer.
    2. 
      
  2. Open the Logs tab and tap Share (the zip carries the most context).
    3. 
      
  3. Attach it to an issue along with the container and codec of the file, if you know them —
        the player's info panel shows both.
    4. 
    

    

      Exports contain file names, URIs, sizes, codec identifiers and the app's own events. They never
      contain the video itself.
